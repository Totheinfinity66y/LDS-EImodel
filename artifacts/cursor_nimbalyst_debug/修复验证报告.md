## 结论

## 原因及修复

Cursor 注册的服务器名是 `nimbalyst`，启动本机 stdio 桥接器。桥接器默认合并 core、host、trackers、situational 路由，但存在两个缺口：

1. host 白名单只包含部分读取工具，缺少 `spawn_session`、`create_session`、`send_prompt`、状态与结果检查等子对话入口。
2. 文件中已有只读记忆路由 `/mcp/ext/memory`，默认合并列表却未包含该路由，导致其工具从目录中消失。
3. 真实 Cursor 调用还会把布尔值和数值编码成字符串，例如 `includeFullResponse="false"`。上游将该非空字符串按真值处理，实际返回了完整回复。桥接器现在按上游真实 schema 将明确的 `"false"`/`"true"` 及规范有限数字字符串转回对应类型；字符串字段保持原样，不猜测 JSON 字符串。元数据仍走原有独立严格校验。

本次补齐上述入口，保留准确会话身份校验与工作区校验。没有新增记忆写入、删除、模型下载或权限设置功能；未修改聊天数据库、应用包或 Cursor CLI 安装文件。
